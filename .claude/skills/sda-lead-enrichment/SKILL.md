# Збагачення лідів SDA: етап 2

Мета — щоб до етапу 3 кожен лід, що пройшов фільтр, мав **перевірений** сайт (або чесне «не знайдено»), сторінку компанії в LinkedIn і базові факти про компанію. Етап 3 тоді не витрачає звернення на пошук сайту і одразу йде на сторінки команди й кар'єри.

**Чому окремий крок.** Перебір доменів дає багато сайтів, але в Bits & Pretzels 2026 15–25 % таких сайтів виявились чужими (припарковані домени, однофамільці, інша галузь). Помилковий сайт шкодить більше, ніж порожня клітинка: на ньому етап 3 знаходить «сигнали» чужої компанії, а лідген пише не тій людині.

## Кого обробляти

`python3 scripts/select_rows.py "<… - етап 1.csv>" --limit 12` показує картки рядків, які потребують збагачення:
- **S** — «Базово підходить» = TRUE, сайту немає;
- **A** — невизначені, CEO / фаундер з описом, сайту немає;
- **B** — невизначені, CEO / фаундер **без опису** (з сайтом чи без): їм найбільше потрібен опис компанії.
Tier 3 / Investor / Partner / дублі / група C — не обробляти. Порядок: S → A → B.
Партії по ~12 рядків; кожну партію одразу зберігати в `batches/bNN.json`, щоб після перерви продовжити (`--skip-done batches/`).

## Режим 1 — Claude шукає сам

Для кожного рядка, бюджет **1–3 звернення до вебу** (максимум 4):

1. **Домен з корпоративного email** (у картці «домен email») — відкрити, звірити.
2. **Вебпошук:** `"<Компанія>" <2–3 характерні слова з pitch>` → `"<Ім'я Прізвище>" "<Компанія>"` → `"<Компанія>" <місто/країна>`. Для групи B (опису немає): `"<Ім'я Прізвище>" <посада> "<Компанія>"`.
3. **Сторінка компанії в LinkedIn** (через пошук `site:linkedin.com/company "<Компанія>"`) → поле website. Відкривати точково; особисті профілі масово не відкривати (умови LinkedIn) — колонка «особистий LinkedIn» лише підказка.
4. **Підбір домену** (`назва.com / .ai / .io / .de`) — лише в останню чергу і лише зі строгою перевіркою нижче.

**Перевірка «це та сама компанія» — обов'язкова.** Сайт записується, лише якщо є хоча б одна сильна ознака:
- ім'я контакту є на сайті: Team / About / Über uns / **Impressum** (на німецьких сайтах там Geschäftsführer — найкращий доказ);
- продукт на сайті збігається з pitch (той самий продукт + 2 характерні слова, не «AI», «platform», «solutions»);
- сайт вказаний на сторінці компанії в LinkedIn, і ця сторінка збігається за назвою й продуктом.
Відкидати: припарковані домени / «for sale» / заглушки хостингу / 404; іншу галузь; іншу країну без зв'язку з pitch; EU-проєкти й спільноти з тією самою назвою; інший бізнес засновника. Сумнівний домен — не в `website`, а в «Додатковий контекст»: «кандидат сайту (не перевірено): <url> — чого бракує».

**Під час того ж відкриття сторінок** (без окремих запитів) записати те, що видно:
| Що | Куди (наявні колонки) | Формат |
|---|---|---|
| Що робить компанія, 1 речення | «Додатковий контекст» | `Продукт: <для кого і що> (<url>)` |
| Країна штаб-квартири, рік заснування | «Додатковий контекст» | `HQ: Мюнхен, DE; засн. 2023` |
| Сторінки команди й кар'єри | «Додатковий контекст» | `Команда: <url>; Кар'єра: <url>` (лише URL — ролі й дати шукає етап 3) |
| CEO / CTO / технічний співзасновник | «чи є CTO» | `так — <Ім'я>, CTO (<url>)` / `ні — на сторінці команди лише нетехнічні засновники (<url>)` / не заповнювати, якщо сторінку команди не відкривали |
| Розмір | «Розмір команди» | `~25 (LinkedIn, <url>)` / `11–50 (LinkedIn)` |
| Що не вдалося | «Потрібно від лідгена» | `сайт не знайдено — подивитись у профілі застосунку`, `JS-сайт не відкрився` тощо |

**Не робити на цьому етапі:** не ставити Tier, не шукати раунди й вакансії з датами, не писати гачки — це етап 3. Якщо з сайту очевидно, що компанія — агенція / дев-шоп / фонд / офлайн-бізнес, написати це фактом у «Додатковий контекст» (етап 3 врахує), але Tier не змінювати.

## Режим 2 — перевірити й доповнити результат Codex

Коли пошук сайтів віддали Codex (промпт — `references/codex_site_search_prompt.md`, колонки v2):
1. `python3 scripts/import_codex.py "<результат Codex.csv>" batches/a00_codex.json` — імпортує знайдене з позначкою «Codex — НЕ перевірено» і друкує список рядків для перевірки: усе, що знайдено **підбором домену**, з впевненістю не «висока», кандидати, неправильні LinkedIn, плюс вибірково ~10 % «високих».
2. Для кожного рядка зі списку — перевірка за правилами режиму 1 (1–2 звернення: відкрити сайт → Impressum / Team / звірити з pitch). Підтвердилось — у батчі `bNN.json`: `"Джерело сайту": "етап 2, перевірено Claude (знайшов Codex): <доказ>"` + доповнення (продукт, HQ, команда, CTO, розмір). Не підтвердилось — `"website": ""` і пошук як у режимі 1.
3. Рядки, де Codex нічого не знайшов, — режим 1.
4. Якщо вибіркова перевірка «високих» показала ≥ 2 помилки з 10 — перевірити всі «високі» з цього методу.

## Формат батчу і запис

```json
{"57": {"_company": "Example GmbH", "website": "https://example.com", "LinkedIn компанії": "https://www.linkedin.com/company/example",
        "Джерело сайту": "етап 2, перевірено Claude: Impressum — GF Max Müller",
        "чи є CTO": "так — Anna Weber, CTO (https://example.com/team)",
        "Розмір команди": "11–50 (LinkedIn)",
        "Додатковий контекст": "Продукт: AI-планування змін для лікарень (https://example.com); HQ: Мюнхен, DE; засн. 2023; Команда: https://example.com/team; Кар'єра: https://example.com/jobs"},
 "61": {"_company": "…", "Потрібно від лідгена": "сайт не знайдено (2 пошуки) — подивитись у профілі застосунку", "Джерело сайту": "етап 2: не знайдено"}}
```
`"Джерело сайту"` починати з «етап 2, перевірено Claude: <доказ>» — етап 3 тоді довіряє сайту і не шукає його знову.

`python3 scripts/write_enrichment.py "<… - етап 1.csv>" batches/ "<… - етап 2.csv>"` — записує в копію (наявні колонки; «Додатковий контекст» і «Потрібно від лідгена» дописуються, а не перезаписуються). Оригінал не змінюється. Далі етап 3 (sda-lead-signals) запускається на файлі `- етап 2`.

## Звіт
- скільки рядків оброблено (S / A / B), скільки сайтів знайдено й перевірено, скільки «не знайдено», скільки кандидатів;
- у режимі 2: скільки сайтів Codex підтвердилось, скільки виявились чужими (окремо для підбору домену);
- скільки рядків групи B отримали опис продукту;
- компанії, які з сайту виглядають як агенція / фонд / поза ICP (для етапу 3);
- вартість: звернень до вебу всього і в середньому на рядок.

## Робота як агент (без користувача)

- **Вхід, обов'язково:** файл після етапу 1 (`… - етап 1`). Для режиму 2 — ще файл від Codex.
- **Самостійно:** обирати рядки через `select_rows.py`, працювати партіями по ~12, зберігати кожну партію в `batches/bNN.json` і продовжувати з `--skip-done`.
- **Обов'язково в кожному записі:** `_company` (скрипт запису звіряє з таблицею і зупиняється при зсуві) і `Джерело сайту`, якщо записано сайт.
- **Зупинитися і повернути питання**, якщо: у файлі немає колонок етапу 1 («Базово підходить», «Група»); скрипт запису зупинився через зсув; у режимі 2 вибіркова перевірка показала, що більше половини «високих» сайтів Codex чужі (результат Codex непридатний).
- **Ніколи:** не змінювати Tier, «Статус», «Базово підходить», основний ICP (скрипт це блокує); не записувати сайт без доказу; не відкривати масово особисті профілі LinkedIn.

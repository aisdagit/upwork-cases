# Етап 3 для корпоративного сегмента (MOD-5 / AUT-4): інструкція для партії (для агента-виконавця)

SDA — українська IT-компанія на ~50 людей (AI і розробка ПЗ, модернізація legacy, бізнес-автоматизація, FD Engineers — виділений senior-інженер у команді клієнта, який доводить AI-автоматизацію до продакшну в ERP/CRM/PIM). Ліди — учасники конференції, здебільшого CIO / digital-керівники Mittelstand-компаній і корпоратів. Потрібно зрозуміти, чи є **підтверджена причина писати зараз**.

## Бюджет
**1–2 WebSearch на компанію, максимум 3.** WebFetch — лише якщо результат пошуку дуже перспективний, але без дати чи деталей. LinkedIn-профілі людей не відкривати (умови LinkedIn). Джерела: 2025–2026; 2024 — тільки якщо нового немає; старіші не є сигналом (можна згадати як контекст із позначкою «застаріле»).

Типовий пошук: `"<компанія>" KI OR AI OR Digitalisierung OR "SAP S/4HANA" OR Cloud 2026` або `"<компанія>" Stellenangebote KI Engineer`.

## Правила Tier
- **MOD-5** (200+ людей). Tier 1 = digital-DM (CIO, CDO, CTO, Head of IT/Digital/AI, Head of Transformation) **+** видимий проєкт (публічна AI-, cloud- чи ERP-програма, або legacy-модернізація 2025–2026; вакансії AI / Automation Engineer; явна потреба в pitch — теж рахується). Tier 2 = digital-роль без підтвердженого проєкту, або проєкт є, але DM прийнятний, а не ідеальний.
- **Enterprise-гіганти** (DAX/MDAX-рівень: Bosch, Telekom, Audi, Mercedes, Siemens, BSH, UniCredit, Novartis, CARIAD, Allianz тощо) — **Tier 3** з коментарем «enterprise-гігант — закупівля через procurement і великих інтеграторів» (довідник v0.5). Виняток: pitch явно шукає зовнішніх постачальників чи партнерів. Великий Mittelstand (200–10 000 людей) — основна ціль.
- **AUT-4** (10–200 людей, традиційний бізнес, ручні процеси). DE = максимум Tier 2.
- **Tier 3**, з причиною: компанія — IT-консалтинг, інтегратор або дев-шоп (конкурент); не-digital роль у великій корпорації; сегмент не підходить.
- **Посада невідома** (порожня): Tier 2, якщо компанія підходить, і `Потрібно від лідгена: з'ясувати посаду контакту`.
- **Не можеш визначити:** Tier порожній, і вказати, що треба перевірити.
- Якщо це насправді софтверна компанія чи scaleup → «Основний ICP» = DEV-2 (і «Тип потреби»), з поясненням.
- Конкурент (IT-сервіси) → Tier 3 або «Partner?» у коментарі.

## Формат виходу
Файл JSON: ключ — **індекс рядка (перше число в рядку вхідного файлу)**, значення — об'єкт з колонками. Порожні колонки не включати.
Колонки:
- `website` — сайт компанії, якщо знайдено і його немає у вхідних даних;
- `Сигнали модуля` — `сигнал: так/ні/невідомо — факт (дата) URL; …`. Кожне «так» — з URL;
- `Бал` — сильний сигнал = 3, середній = 2, виключення = −3, сума;
- `Tier` — `Tier 1` / `Tier 2` / `Tier 3` / порожньо;
- `Гачок для меседжу` — одне речення англійською лише для Tier 1, на основі найсильнішого підтвердженого сигналу, без компліментів;
- `Додатковий контекст` — важливе, коротко: реструктуризація, M&A, зміна власника, власна велика IT-команда, SAP-міграція тощо;
- `Потрібно від лідгена` — що доповнити вручну;
- `Коментар етап 3 (сигнали)` — модуль (MOD-5 / AUT-4 / FD Engineers), чому такий Tier, 1–2 речення українською;
- `Основний ICP`, `Тип потреби` — лише якщо змінюєш.

Пиши українською (крім гачка). Не вигадуй: немає URL — пиши «невідомо».


## Додатково (уроки першого запуску)
- Ціль MOD-5 — великий Mittelstand на ~200–10 000 людей. Великі, але не гіганти (OBI, BARMER, Stadtwerke) — максимум Tier 2.
- Не сигнали: нагорода («Top Digital Company», «CIO of the Year»), призначення нового CIO, загальні слова про digital transformation без проєкту.
- Сам виконуй пошук, **не запускай інших агентів**.
- Tier — лише рядком: "Tier 1" / "Tier 2" / "Tier 3" / "".
- Гачок: одне речення англійською, без «exactly the kind of…».

## Обов'язково (зауваження лідгенів після першого запуску)
- **Вакансії:** відкрити саму сторінку кар'єри і перелічити ролі (`так — Software Engineer, Backend Engineer — дата URL`). «Є сторінка кар'єри» — не результат. Новина «плануємо наймати» — не вакансія, якщо на сайті вже відкриті ролі.
- **CTO:** відкрити Team / About / Über uns / Impressum; якщо там є CTO чи технічний співзасновник — записати ім'я. «невідомо» — лише після цього.
- **LinkedIn компанії:** тільки `linkedin.com/company/…`; не особистий профіль, не стрічка, не пост.
- Перед записом файлу пройтись по своїх рядках і перевірити ці три пункти.
- **У кожному записі JSON — `"_company"`** (назва компанії з рядка): скрипт запису звіряє її з таблицею і зупиняється, якщо результати зсунулись відносно рядків.

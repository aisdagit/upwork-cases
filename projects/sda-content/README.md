# SDA LinkedIn content — інструкція для тестування

Набір із 4 скілів для Claude Code, які готують пости LinkedIn для **CEO, сторінки SDA і Kateryna**. Мета тесту — зрозуміти, чи виклала б ти ці пости, і зібрати твої правки, щоб покращити скіли.

## 1. Встановлення (один раз, ~10 хвилин)

1. Розпакуй архів у зручне місце, наприклад `Documents/sda-content`.
2. Потрібні **Claude Code** (CLI або вкладка Code у застосунку Claude) і **Python 3**. Перевірка: `python3 --version` у терміналі (на Windows — `python --version`; тоді в командах пиши `python` замість `python3`).
3. Відкрий Claude Code **саме в цій папці**:
   - у терміналі: `cd ~/Documents/sda-content` і далі `claude`;
   - або в застосунку Claude: вкладка Code → обрати папку `sda-content`.

   Скіли лежать у `.claude/skills/` і підхоплюються автоматично. Перевір: напиши `/` — у списку мають бути `sda-content-plan`, `sda-content-angle`, `sda-content-writer`, `sda-content-critic`.

## 2. Оновити дані перед запуском

У папці `data/` лежать копії від 07.10.2026. Перед тестом заміни їх свіжими:
- **Контент-план:** Google-таблиця → аркуш з постами → Файл → Завантажити → CSV → збережи як `data/content_plan.csv`.
- **Реєстр конференцій:** аркуш «Реєстр конференцій» → CSV → `data/conferences.csv`.
- **Telegram CEO** оновлюється сам (скіл плану запускає `tools/tg_parser.py`). Якщо інтернет блокує t.me — нічого страшного, буде архів станом на 12.10.

## 3. Тест: 10 постів на 13–24 жовтня

Запускай по черзі, після кожного кроку переглядай результат:

| Крок | Що написати Claude | Що з'явиться |
|---|---|---|
| 1 | `/sda-content-plan 10 постів на 13.10–24.10` | `output/2026-10-13_2026-10-24/план.md` + файли постів `01_…md`, `02_…md`, … |
| 2 | `/sda-content-angle для всіх постів плану` | у кожному файлі поста — розділ «Бриф» |
| 3 | `/sda-content-writer для всіх постів` | розділи «Текст» і «Візуал» |
| 4 | `/sda-content-critic для всіх постів` | розділи «Критик» і «Фінальний текст» + `для_таблиці.csv` |

**Порада:** усе по одному посту (всі 4 кроки) переглядати найзручніше у файлі поста: там зібрано план, бриф, текст, критика й фінальну версію.

Якщо скіл питає автора (наприклад, «скинь фото з конференції» або «яка історія з клієнтом»), можна:
- відповісти самій, якщо знаєш;
- написати «немає відповіді» — тоді writer зробить каркас з позначками `[ПОТРІБНО ВІД АВТОРА]`.

**Важливо:** план складається **наосліп**, без твого плану на ці дати. Після тесту порівняй: що система взяла так само, що інакше, що краще чи гірше.

## 4. Відгук — найважливіша частина

Заповни `feedback/feedback.csv` (відкривається в Excel або Google Sheets). По кожному посту:
- **Оцінка:** виклала б / з правками / ні.
- **Що змінила** і **чому** — найцінніша колонка: саме з неї оновлюються правила скілів.
- **Твій фінальний текст**, якщо правила, — вставити повністю.

Окремим рядком — оцінка **плану в цілому** (етап «план»): чи такий розподіл тем, чи все враховано, чого бракує.

## 5. Що надіслати назад

Заархівуй і надішли папки **`output/`** і **`feedback/`**.

## Що є в папці

- `.claude/skills/` — 4 скіли;
- `kb/` — правила (`00_rules.md`), профілі CEO, SDA і Kateryna, банк позицій CEO;
- `data/` — контент-план, конференції, архів Telegram CEO;
- `tools/` — скрипти (`context.py` — вибірки даних, `tg_parser.py` — Telegram, `lint.py` — перевірка AI-стилю, `collect.py` — CSV для таблиці);
- `CLAUDE.md` — короткий контекст для Claude.
